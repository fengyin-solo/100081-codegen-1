# 港口集装箱作业调度平台

面向船舶靠泊、集装箱装卸、堆场堆存、闸口进出与理货结算的一体化港口作业调度后台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 泊位计划靠泊编排流程

泊位计划（`berth`）有完整的靠泊编排状态机：

```text
待编排 ──确认排定──▶ 已排定 ──确认靠泊──▶ 靠泊中 ──确认离泊──▶ 已离泊
  ▲                    │ 退回待编排（填原因）   │ 退回排定（填原因）
  └────────────────────┴───────────────────────┘
```

- **逐步流转**：只能沿主线逐档前进，越档/重复操作当场拒绝并说明原因；每个状态都支持退回上一环节（待编排除外）。
- **步步留痕**：登记、排定、靠泊、离泊、退回、改计划都会在 `history` 中追加一条记录，含操作时间、经办人、起止状态、退回原因与字段变更明细。顶栏可切换经办人（换班时改成本人，持久化保存）。
- **改船改泊约束**：计划不在「待编排」状态时，修改靠泊船舶或泊位编号会被拒绝，必须先逐档退回并写清原因；已离泊计划不能再改船改泊。
- **看板与列表一致**：编排看板（四列状态泳道）与计划列表共用 `GET /api/berth` 同一份数据和状态口径，操作后两处同步刷新。
- **刷新不丢上下文**：当前视图（看板/列表）与打开的计划明细保存在浏览器本地，刷新后仍停在最近一步，明细抽屉里的操作痕迹时间线让接班人员直接接上。
- **泊位冲突不静默覆盖**：确认排定（以及已排定/靠泊中计划调整时段）时，校验同泊位计划时段是否与其他「已排定/靠泊中」计划重叠（首尾相接不算冲突），冲突时返回占用计划编号、船舶、时段并拒绝写入。
